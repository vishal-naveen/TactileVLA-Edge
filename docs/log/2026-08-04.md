## [SW] Environment verified on the macOS bring-up machine

LeRobot 0.5.2 installed editable from the fork. Confirmed working:

- `scservo_sdk` imports (via `feetech-servo-sdk` 1.0.0). Without it, no servo communication is
  possible at all — this was the blocking gap.
- The `so101_follower` config constructs a real Feetech bus bound to all six joints:
  `shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_roll, gripper`.
- `lerobot-find-port` enumerates serial ports, which exercises the pyserial path.
- ffmpeg 8.0.1 has `libsvtav1`, required for dataset video encoding.

Installed to close the gap: `feetech-servo-sdk`, `pyserial`, `deepdiff`, `pynput` 1.8.2,
`rerun-sdk` 0.26.2. Still outstanding: `torchcodec`, needed only to read datasets back, and
version-constrained by PyTorch 2.10 — deferred until data collection.

## [SW] Two documentation traps found

1. Circulating setup guides pin `pynput==1.6.8` and `rerun-sdk==0.23`. Both are *below* LeRobot
   0.5.2's stated minimums (`>=1.7.8` and `>=0.24.0`). Following that advice creates the
   dependency conflict it purports to fix. Resolved versions from LeRobot's own `pyproject.toml`
   instead. Recorded in ADR-0002.
2. LeRobot renamed the implementation directories to `so_follower` / `so_leader` while keeping the
   registered config names `so101_follower` / `so101_leader`. The `--robot.type=so101_follower`
   form is correct and should not be "fixed" to match the directory names.
