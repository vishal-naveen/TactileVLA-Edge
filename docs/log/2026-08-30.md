# 2026-08-30

## [INTEGRATION] Phase 2 closed — vision-only baseline works

160 episodes recorded 8–11 August, both policies trained on the RTX 3060, both evaluated on the
physical arm. ACT 18/20, SmolVLA-450M 16/20. Full protocol and limits in
[`results.md`](../results.md).

The result worth keeping is not the success rates — 20 trials cannot separate them — but that
both policies completed the task in cell B2, which appears in zero training episodes.

## [SW] The cell log is append-only, and counting its rows is wrong

`noodlegrid_20260808_1807-cells.csv` has **283 rows for 160 episodes**. A re-recorded episode is
logged again under the same `episode_index`; several were re-recorded up to four times during
the session's recovery steps.

Counting rows per cell reports a wildly unbalanced dataset (B1 71, B3 24). Deduplicating to the
last row per `episode_index` — the take that actually survived into the dataset — gives exactly
**20 episodes in each of the 8 recorded cells**.

This nearly reached a published figure. `tactilevla-gridfig.py` now does the deduplication and
regenerates the figure from the session's own geometry and log, so the two cannot drift apart.

## [SW] Encoder options must be strings, and only `set_if` casts them

`VideoEncoderConfig.get_codec_options()` assigns directly to `opts` in the hardware-encoder
branches instead of going through `set_if()`, which is the only path honouring `as_strings=True`.
PyAV requires option values to be `str`, so the first frame raises:

```
RuntimeError: Encoder thread for observation.images.top crashed:
Argument 'value' has incorrect type (expected str, got int)
```

This breaks every hardware encoder path in LeRobot 0.5.2 — `h264_videotoolbox` and
`hevc_videotoolbox` on macOS, and `h264_nvenc` / `hevc_nvenc` on the training machine. Caught by
a 3-episode shakedown before the real session. Fixed in the fork; upstream-worthy.

**Lesson:** the shakedown paid for itself. A three-episode run cost ten minutes and would
otherwise have failed at episode 1 of 160.

## [SW] What Phase 2 did not touch

No tactile data was recorded, trained on, or evaluated. `software/tactile/`, `dataset/`,
`fusion/`, and `eval/` remain planned modules. The README and `COMPATIBILITY.md` now say so
explicitly rather than implying a tactile pipeline exists.

AnySkin is formally dropped in favour of servo-load readout (`Present_Load`, register 60), which
needs no additional hardware. The sensor was never built.
